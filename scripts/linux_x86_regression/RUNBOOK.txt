Linux x86_64 regression bundle for commit 955ae841

Scope
  Focused standalone CMake build: metric, Turbo, Flat, clustering and legacy IVF.
  RABITQ_SUPPORTED=0 and DISKANN_SUPPORTED=0, matching the previous macOS harness.
  This is not a full repository/product/recall/concurrent-throughput validation.
  Use the normal root CMake/CI build separately for product integration coverage.

Requirements
  Linux x86_64; git; Python 3; CMake >= 3.26; Ninja; C++17 GCC or Clang;
  taskset (util-linux). Use the same compiler/environment for all versions.
  Internet access is needed to fetch the two dependency submodules.

The driver makes no git commits or pushes, and does not install dependencies.
This portable bundle was syntax checked and CMake-configured on macOS; Linux
execution has not yet been performed. Do not treat this as a Linux pass result.

Build and correctness (same shell)
  python3 "$BUNDLE/run.py" build --root "$RUN" --jobs 8
  python3 "$BUNDLE/run.py" correctness --root "$RUN"

Correctness builds/runs all 10 metric and 27 Turbo test executables plus two
Flat tests, three clustering tests, the new legacy IVF test, and 13 selected
existing IVF searcher tests (44 executables). Additional executions write 200
fixtures with the pre-refactor implementation, read them with fixed code, and
check before-version IVF. Each IVF fixture pass checks 28,800 result lists.
Architecture-dependent skip/pass counts may differ from macOS.

Performance (run only after builds/tests finish; no concurrent benchmark jobs)
  python3 "$BUNDLE/run.py" perf --root "$RUN"
  # Optional: select a quiet allowed logical CPU, e.g. --cpu 2.

The default is the lowest CPU in sched_getaffinity(0). All versions are pinned to
the same CPU via taskset and run serially. Avoid another workload on that CPU
or its SMT sibling. Build flags use the repository's AUTO_DETECT_ARCH path;
per-ISA objects and runtime dispatch are retained. Do not change ISA flags for
only one version. Generic and -march=native builds are different experiments.

Microbenchmark scope: 504 raw cases (6 types x 2 metrics x 21 shapes x 2 dims)
and 32 MIPS/record adapter cases, dimensions 128 and 512. Each uses adaptive
repetitions >= 2 ms thread CPU time and median of five rounds.
IVF scope: 24 cases, 8193 rows, one list, 16 queries, top-k 10, scan_ratio=1,
warm-up queries and median of seven rounds. Timings are wall-clock us/query.
Every group runs three fresh processes per version in rotated order.

The same copied IVF source and benchmark sources are compiled against all
versions; no fixes are cherry-picked into parent or before. LEGACY only selects
the old raw matrix API and its FP16 reference limitations. Parent FP16 1x1 raw
oracle checks are skipped due to reduced precision; parent FP16 adapters allow
1% pair-reference tolerance. Fixed code retains strict checks. Performance
equality with parent FP16 therefore is not an accuracy-equivalent comparison.

For every comparison CSV:
  fixed_vs_parent = fixed / pre-refactor time
  fixed_vs_before = fixed / pre-fix time
  < 1 means faster; > 1 means slower; change_*_pct is percentage time change.
  Inspect min/max across the three process medians as well as the median ratio.
  Do not compare Linux absolute timing against macOS or infer equivalence from
  one percentage cutoff. Any correctness failure must be investigated.
