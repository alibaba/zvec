macOS/ARM64 复验说明 —— Linux x86 残余回退最终候选(2026-11-09)
=====================================================================

给 macOS 上的 agent:请先读本文件,再读交接包里的 RESIDUAL_X86_REPORT_zh.md。

1. 背景
--------
分支 fix/legacy-matrix-distance-performance 的 HEAD 9819c706 在 Linux x86(gcc 13.3,
Xeon 6982P-C)上验证未通过:对齐属性方案无法收敛,原始矩阵 >5% 项为 23(vs 7abc63fe)/
27(vs 955ae841)。Linux 侧随后做了最小修复,得到最终候选:
  - 相对 9819c706 只改 src/turbo/distance/matrix.h(patches/final_vs_9819c706.patch);
  - 删除两处 GCC __attribute__((noinline, aligned(64), optimize("align-loops=64")));
  - INT4 ComputePackedColumns:Rows<=4 保留原循环,Rows>=8 改为"查询半字节展开 +
    每个矩阵字 8 个表行指针"的内核;
  - INT4 ComputeSingleColumn(uint8_t 分支):利用半字节对表的对称性,先按查询半字节索引,
    把 8 个查询表行提升到行循环外;
  - 9819c706 的 x86 INT4 记录 n==1 批处理路径(quantized_integer_metric.cc)和全部测试保持不变。
x86 结果:44 个程序 511 通过/0 失败;200 个旧索引 fixture 读写正常;两轮性能回归中
原始矩阵 >5% 项降至 2/2(均为代码完全相同的 1x1/2x1 布局项),适配器与 IVF 为 0 项;
13 项整数矩阵回退有 12 项两轮快于 7abc,INT4 记录量化 32x1 ≈0.52× before。
详细数据在交接包 RESIDUAL_X86_REPORT_zh.md 与 candidate/analysis/。

**这些改动没有 x86 宏保护,ARM64/Clang 会编译同一份 INT4 内核。x86 已验证,
macOS 尚未验证;在 macOS 复验完成之前不要宣称两平台无退化。**

3. 需要在 macOS 上做的事
------------------------
(1) 正确性(与 7abc/9819c706 两轮相同的范围):
    tests/turbo/*_test、tests/core/metric/*_test(尤其 turbo_matrix_test、
    quantized_integer_metric_test、turbo_metric_adapter_test 含新增
    Int4RecordMatricesPreserveStoredMoments)、ivf_legacy_matrix_test、
    legacy_quantized_index_test、flat_quantizer_distance_test、ivf_searcher_test、
    clustering 测试。期望:与 9819c706 同样全部通过(x86 为 511 通过)。
    旧索引兼容:parent(499eab89)写 fixture、候选读 fixture,与前两轮一致。

(2) 性能(同一 toolkit:matrix_sweep 504 / adapter_sweep 32 / legacy_ivf_comparison 24,
    固定核心,两轮,每轮 3 进程取中位数),基线至少含 9819c706 和 7abc63fe,最好也含 955ae841:
    重点形状:
      - INT4 多列 Rows>=8(8x8, 16x8, 16x16, 32x8, 32x16, 32x32, 32x2, 32x4, 16x2):
        x86 为 0.56–0.94× 7abc,预期 ARM64 也应明显变快;若 ARM64 反而变慢,记录并反汇编
        (Clang 对 query_nibbles 栈数组与 rows[8] 指针数组的处理可能不同)。
      - INT4 Rows<=4 多列(2x2, 4x2, 4x4):走原循环,预期持平。
      - INT4 单列(2x1 … 32x1):x86 为 0.75–0.83×;ARM64 预期持平或更快。
      - INT8 全部、FP16/FP32/FP64/INT16:补丁不触及,预期持平(只有布局噪声)。
      - 适配器 INT4 RecordL2/RecordIP 32x1 与 32x32、IVF INT4 record:n==1 批处理路径是
        x86-only,macOS 上这部分应与 9819c706 相同。
    判定:任何在两轮都 >5% 的项都要定位(反汇编对比 9819c706),不要只报比值。

(3) 回传:macOS 补丁(如有)、两轮对比表、原始 CSV、反汇编证据;明确写出
    "macOS 正确性/性能结果 + x86 结果 = 两平台状态",由人决定是否合入。
