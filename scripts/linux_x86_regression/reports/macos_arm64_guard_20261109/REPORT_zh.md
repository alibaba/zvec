# ARM64 大多列最小修复与回归结果

2026-11-09，Apple M3 Pro / macOS 26.6.2 / AppleClang 15。

**本次目标已修复：之前 12 项 INT4 大多列矩阵回退 + 2 项 INT4 MIPS 32×32 回退均消除；相对调整前候选，三组性能均没有新增两轮共同 >5% 的回退。** 正确性与旧索引兼容通过。
范围限定：完整 sweep 相对历史基线仍有 FP16 1×1 布局相关回退，不能表述为所有形状都零回退；另有只对部分基线复现的波动项，定点复测已单独记录。本轮未在 Linux x86 服务器重跑。

## 1. 具体改动

独立工作树 `source/` 基于 9819c706，先应用已校验 x86 最终候选，再只修改 `src/turbo/distance/matrix.h:151`：
```cpp
if constexpr (Rows <= 4
#if defined(__aarch64__) || defined(_M_ARM64)
              || Columns >= 16
#endif
) {
  // 原直接提取 packed word 的循环
} else {
  // 查询半字节展开的循环
}
```

- ARM64 Columns≥16 使用旧循环，消除 query_nibbles 落栈后逐字节读取的额外成本。
- ARM64 Rows≤4 继续原循环；其余 Columns=2/4/8 的优化和所有 INT4 单列查询表行提升保留。
- x86 条件和实现保持 Linux 已验证候选的内容；未修改记录量化公式、存储格式、IVF 或测试期望。
- 相对调整前候选只有一个编译期条件变化，差分 7 行新增/1 行删除（含注释与条件格式）；相对 9819 的完整差分仍仅 matrix.h。
- 主分支仍为 c65ac889 且干净；本轮改动仅位于独立工作树，没有提交、推送或合入。

补丁：`buildinfo/arm64_guard_vs_unguarded.patch` 适用于已经应用 x86 final 的源码；`buildinfo/guarded_vs_9819c706.patch` 是可直接应用到 9819/c65 的完整候选。两者勿重复应用。

## 3. 性能方法与版本

每轮原始矩阵 504、适配器 32、旧 IVF warm 扫描 24 项；五版本各 3 个进程，交错运行，第二轮反转起始顺序。共 90 个完整基准进程。每进程内部取中位数，再取 3 进程中位数，保留 min/max/原始日志。
版本：955 / 7abc / 9819 / unguarded（上一轮未加 ARM64 条件的 x86 final）/ final（本次候选）。四个对照使用保留的静态二进制重新计时，没有使用旧轮次的性能数字。955/7abc/9819 原始矩阵的代码和常量区地址/哈希一致。
使用同一 toolkit、Release `-march=armv8 -O3 -DNDEBUG`、无全局对齐或新增架构参数。静态 force_load 链接保留工厂注册；统一 USER_INTERACTIVE QoS + taskpolicy -a，**没有硬绑 CPU 核**。matrix/adapter 线程 CPU 计时，IVF warm search_impl 墙钟计时。编译/其他基准与性能运行串行。此调度限制使小形状/墙钟波动需要定点复测。

## 8. 汇编与 x86 检查

- 16×16 / 32×16：全函数静态指令 166→105，直接 [sp] 访问 26→8；32×32：229→111、43→8，恢复历史直接提取循环，避免大查询字节数组落栈。单列优化保留。计数是静态汇编统计，不是硬件事件。
- FP16 warm dispatch 前 31 条归一化指令相同，NEON IP 完整 114 条指令相同；FP64/INT16 raw_numeric 内核归一化指令相同。见 disasm/。
- 对调整前/后完整 matrix_sweep 做 x86_64 交叉编译：预处理 token SHA256 相同，完整 Mach-O 目标文件 SHA256 相同，全部 __TEXT 节相同，见 buildinfo/x86_unchanged.json 与 check_x86_unchanged.py。
- **这项编译检查使用 AppleClang 的 x86_64 Darwin 目标，不是 Linux/GCC 实机性能复跑。** ARM 条件在 x86 被预处理移除；原 Linux final 报告继续作为既有实机证据，本轮没有新 Linux 性能数字。
