优先级与候选实现
================
1. FP16：原始矩阵先用已有 SIMD 批量转换函数将 64 维交错块转换成 FP32，
   再调用 FP32 矩阵内核；固定栈缓冲，不转置、不增加堆分配。
   x86 MIPS FP16 暂恢复 MakeDistanceMatrix(distance()) 的连续 SIMD 路径。
2. INT4 记录量化 32×1：x86 恢复转置后使用连续 SIMD 的适配路径。
3. INT8 记录量化多查询：x86 恢复连续 SIMD 适配路径，保留已有单查询优化。
4. FP32 MIPS 单查询：x86 融合计算 dot + 两端 norm，减少重复读取。
测试调整：FP16 单列 IP 增加极值/尾部检查；记录量化测试仅对主动选择转置的
x86 形状明确断言两次缓冲分配，数值正确性仍然检查，不放宽误差容限。
新增 FP16 IP 极值用例含 65504^2 大数相消，不能对接近零的结果使用相对误差。
该新增用例使用 gamma_n * sum(abs(products)) 的 FP32 累加误差界，并同时检查
动态/模板入口一致性、输出边界和零分配；原有 L2、整数及普通 FP16 测试判定不变。

四版本比较与验收
================
compare_followup.py 输出 matrix/adapter/ivf_four_versions.csv 和汇总 JSON。
数值是 candidate / baseline 耗时比；小于 1 更快，1.05 为 +5% 回退。
它不自动宣称 PASS。结合两轮中位数、min/max 以及 parent/before 漂移判断。

优先项逐个列全：
- FP16 raw L2/IP：全部形状，尤其 32×1 128/512、64 维 tile 尾部。
- FP16 MIPS：32×1、32×32，128/512。
- INT4 RecordL2/RecordIP：32×1，128/512；同时看旧记录量化 IVF。
- INT8 RecordL2/RecordIP：32×32，128/512；32×1 必须保留上次收益。
- FP32 MIPS：32×1，128/512；32×32 和所有 injection 正确性不得退化。
- FP16 L2 IVF：128/512，验证内核优化是否传到旧列式查询。

至少同时对照 previous_fix、before、parent，不能只说优于最慢的版本。
候选相对 previous_fix 两轮均 >5% 的项目视为新回退，必须定位并修复或明确保留为未完成项。
优先项相对 before/parent 仍 >5%，也必须继续分析；不能“恢复到 parent”就忽略 before 更快。
其余继承自重构的 1×1、INT4 多查询、INT16/FP64 等残余单独列出，不能称为全部解决。
把 >5% 的三个集合及交集分别计数，避免旧报告将 before 回退总数误写成排除 parent 后的子集数。
若原样 fallback 仍稳定慢于 before，要比较编译参数、ISA 分派和连续 pair 内核，
不能先归因为测试噪声。若环境基线本身漂移 >5%，先重测同一用例。
