验证 fix/legacy-matrix-distance-performance 分支对旧矩阵距离调用链的修复，
重点检查旧记录量化 INT8/INT4 的 32×1 路径、原始矩阵内核和 MIPS 适配层。

3. 相比修复前恢复了多少性能？相比重构前还剩哪些回退？

matrix_sweep.cc、adapter_sweep.cc、ivf_legacy_matrix_test.cc、计时头文件和说明。
拉取本分支最新提交即可获得工具，无需下载额外压缩包。执行脚本来自包含工具

三、验证范围与结论边界

这是相关模块的独立构建，覆盖 metric、Turbo、Flat、聚类和旧 IVF。
RABITQ_SUPPORTED=0、DISKANN_SUPPORTED=0；不是整仓或完整产品验证。
不包含生产规模数据、召回率、并发吞吐以及自动 ASan/UBSan 检查。

当前普通行式 IVF 的 Turbo quantizer 路径与旧列式、旧记录量化兼容路径需要
区分。这里的旧 IVF 测量不能泛化为所有 IVF 查询收益。MIPS 微基准测量的是
矩阵适配层；MIPS IVF 查询使用 inner-product query metric，不能把前者的
提速直接解释为 MIPS IVF 查询提速。

工具包此前只做过脚本语法和 CMake 配置检查，尚无 Linux 执行结果。
macOS 的 497 项通过、0 失败不能替代本次 Linux 验证，也不是必须匹配的计数；
不同架构的条件跳过项可能不同。

六、正确性回归

  python3 "$BUNDLE/run.py" correctness --root "$RUN"

脚本在 fixed 运行 44 个相关测试程序：
  - 全部 10 个 metric、27 个 Turbo 测试程序。
  - 2 个 Flat、3 个聚类测试程序。
  - 新增旧 IVF 测试及现有 IVFSearcher 的 13 个指定测试。

还会运行 parent_write、fixed_read_parent、before_ivf：
  - parent 写出 200 份旧格式索引到 parent-fixtures/。
  - fixed 读取同一批旧索引，按确定性输入和独立参考值校验。
  - before 执行相同 IVF 正确性测试，以帮助区分既有问题。

每轮完整旧 IVF fixture 测试核对 28,800 组结果，覆盖 31/32/33 行边界、尾块、
空倒排、单查询/批查询、search_impl/search_bf_impl、过滤、不同 top-k，以及
MMapFileReadStorage、FileReadStorage、BufferReadStorage。

验收时同时检查退出码和 XML：不能只看日志最后一行，也不能把 skipped 或
disabled 算作 passed。任何崩溃、缺失 XML、未执行、非零退出码都要单独报告。
44 个 fixed 测试程序的统计与额外的跨版本测试统计分开，避免重复计数。

失败时保留首个复现用例及日志，不放宽容差、不跳过失败类型。可以单独复现，
但不得用通过的子集覆盖原始全范围结果。若基线也失败，明确标记基线问题；
正确性未通过时，不给出“验证通过”的总评。性能仅可作为标注清楚的诊断数据。

七、性能回归

等所有编译和正确性测试结束后，选择一个允许使用且空闲的逻辑 CPU。查看：

  python3 -c 'import os; print(sorted(os.sched_getaffinity(0)))'
  lscpu -e=CPU,CORE,SOCKET,ONLINE

执行下面命令；脚本默认选择 affinity 列表中的第一个 CPU。如需指定，统一
增加 --cpu N。避免同一物理核的 SMT 同胞上运行其他负载。

  python3 "$BUNDLE/run.py" perf --root "$RUN"

不要并发执行不同版本的基准，不要边编译边跑基准，也不要使用 sanitizer 或
Debug 二进制测性能。脚本将所有基准固定在同一 CPU，并按轮换顺序串行运行。

测量规模与方法：
  matrix：504 组，6 类型 × L2/IP × 21 个矩阵形状 × 128/512 维。
  adapter：32 组，MIPS 和旧记录量化，32×1/32×32，128/512 维。
  ivf：24 组，8193 条记录、单倒排、16 个查询、top-k=10、scan_ratio=1。

matrix/adapter 使用线程 CPU 时间，每次自适应重复到至少 2 ms，取 5 轮中位数。
IVF 预热后只计查询，取 7 轮的墙钟时间中位数。
每类每版本再运行 3 个新进程，最终取三个进程结果的中位数并保存最小/最大值。

parent 的原始 FP16 1×1 内核精度较低，因此微基准跳过其该项参考值断言；
parent FP16 适配层与 pair 的比较容差为 1%。fixed 保持严格检查。
不要把旧 FP16 的性能数字解释为与修复版本具有相同精度的基线。

八、结果判读和优先检查项

输出目录：RUN/results。
  correctness.json 与逐测试 XML/log：正确性结论。
  matrix_comparison.csv：原始矩阵，单位 ns/矩阵，线程 CPU 时间。
  adapter_comparison.csv：适配层，单位 ns/矩阵，线程 CPU 时间。
  ivf_comparison.csv：旧 IVF，单位 μs/查询，墙钟时间。
  performance.json：含相对 parent 中位数慢超过 5% 的组合列表。
  environment.json、lscpu.txt、benchmark_cpu.json、toolchain.txt：运行环境。

fixed_vs_parent = fixed 耗时 / 重构前耗时。
fixed_vs_before = fixed 耗时 / 修复前耗时。
比例 <1 表示变快，>1 表示变慢。
change_vs_*_pct 是耗时变化百分比，正值表示回退，负值表示改善。
时间减少百分比不等于吞吐提升百分比；报告时写清楚使用哪一种。

优先检查并单独列出：
  1. 旧记录 INT8/INT4，L2/IP，32×1，128/512 维。
  2. 原始 INT4 IP 32×1，以及 INT8 L2/IP、FP16 L2 单查询路径。
  3. MIPS INT8/INT4 32×1，区分已恢复的主要开销与剩余差距。
  4. FP32 L2 16×4；另关注 4×2/512 维和 32×8/128 维。
  5. INT4 多查询，以及全部 504/32/24 组中的其他回退。

比较三轮区间与中位数，不把一次波动直接认定为回退。超过 5% 只是复查提示，
并非自动失败阈值，也不能据此声称其余组合“零回退”。对可疑组合保留原始
结果，再在相同条件下补测，保存到新的结果目录，避免挑选最佳一轮代替报告。
不要用 Linux 的绝对耗时直接对比 macOS，也不要把旧 IVF 收益泛化到所有 IVF。
