## 测量条件

- 机器：Intel Xeon 6982P-C（KVM 虚拟机，AVX-512 可用），Ubuntu 24.04 / Linux 6.8，GCC 13.3，Release `-O3`，AUTO_DETECT_ARCH 分 ISA 编译 + 运行时分派，三版本相同参数。
- 形状：32 条记录 × 1 个查询（32×1），维度 128 / 512。
- 单位：**μs / 矩阵，线程 CPU 时间**（由 ns 换算）。每次自适应重复到 ≥2 ms 取 5 轮中位数，每版本 3 个独立进程取中位数，基准绑定逻辑 CPU 11 串行运行。
- "修复后相对重构前"与"修复后相对修复前"为**耗时变化百分比**，负值表示更快；非吞吐变化。
- 补测列为同条件第二轮（`recheck/`）的修复后相对重构前值，用于确认是否为波动。
- 原始 L2/IP 来自 `matrix_comparison.csv`（直接调用矩阵内核）；MIPS 与记录量化来自 `adapter_comparison.csv`（MIPS / 记录量化矩阵适配层）。MIPS 适配层提速不能直接解释为 MIPS IVF 查询提速。
- Linux 绝对耗时不与 macOS 表格直接比较。

## 要点

- **FP32 原始 L2/IP**：修复后与修复前持平（f7bd575f 在该路径已快于重构前），较重构前耗时 −20%～−52%。
- **FP32 MIPS**：修复前慢 8～9 倍的转置逐对路径已恢复，但较重构前仍慢 17%～26%（两轮复现，为剩余差距）。
- **FP16 原始 L2**：与重构前持平，但较修复前慢 44%～45%——f7bd575f 在该路径快于重构前，修复后未保留。FP16 原始 IP 较重构前 −34%。
- **FP16 MIPS**：较重构前 −30%，但较修复前慢 2.5～2.7 倍（f7bd575f 的 FP16 MIPS 在 x86 上反而是三版本中最快，与 macOS 表现不同）。
- **INT8 原始 L2/IP、INT8 记录量化**：较重构前 −50%～−78%，较修复前 −41%～−71%，两轮稳定。
- **INT8 MIPS**：修复前慢 5 倍的开销已恢复，并较重构前 −13%～−16%。
- **INT4 原始 L2/IP**：较修复前 −63%～−67%，较重构前 −5%～−11%。
- **INT4 MIPS**：较重构前 −17%～−21%，较修复前 −79%～−80%。
- **INT4 记录量化（尚存回退）**：较重构前慢 3%～16%，较修复前慢 28%～76%，两轮复现；是本表中唯一相对重构前稳定回退的记录量化路径。

## 与 macOS 表格的差异提示

- 修复前列的提交不同（见版本口径），FP32/INT8-IP/INT4 原始路径"修复前"数值不可跨表比较。
- x86 上 FP16 路径的修复前（f7bd575f）明显快于重构前和修复后，macOS 表中 FP16 三版本基本持平；x86 的 INT8 MIPS、INT4 MIPS 修复后优于重构前，macOS 表中为 +7%～+9%。
- 原始数据：`results/matrix_comparison.csv`、`results/adapter_comparison.csv`、`recheck/results/*.csv`，均含三进程 min/max。
