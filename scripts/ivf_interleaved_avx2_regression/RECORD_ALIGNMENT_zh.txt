旧 record INT8 / INT4 未对齐访问修复：Linux x86 复验
2026-11-16

目标
确认旧 record 的元数据读写不再依赖 float/int32_t 对齐，且字节格式、数值、
旧索引兼容性、实际 IVF 查询性能没有变化。本轮没有改 SIMD 累加或 IVF 分派。
scalar / SSE2 / AVX2 / AVX512 / VNNI 使用同一个固定大小 memcpy 元数据读取器；
RecordQuantizer 写入及反量化也使用 memcpy。NEON 已使用安全读取，本轮未改。

版本和包
基线是 e2ac9ee02a72b2da2265003c17b27357942a2d0d（已包含上一轮 AVX2 和测试修复），
不能用之前的“增加 AVX2 前”版本作为基线。
修复、macOS 报告和独立交接包随本次提交归档；包内候选源码已冻结，不依赖服务器 HEAD：
  artifacts/ivf-record-alignment-handoff-20261116.tar.gz
  artifacts/ivf-record-alignment-handoff-20261116.tar.gz.sha256
包内 source-base.tar.gz = 基线提交的源码；baseline-vs-head.patch 仅加入专项测试，
candidate-vs-baseline.patch 仅含生产代码修复。两边测试完全相同。
SHA256SUMS 校验全部包内文件；before/after-source-sha256.json 校验完整源码文件集合。
不要运行旧包内的 run.py 或直接运行 reverify.py，本轮入口是 tools/record_alignment.py。

环境
原生 Linux x86_64，建议继续使用上轮 Xeon 6982P-C；必须实际覆盖 AVX2/FMA/F16C、
AVX512 和 AVX512VNNI。机器不支持所需后端会拒绝验收，不能用 skip 当作通过。
CMake >= 3.26、Ninja、Python >= 3.9、C++17 GCC/Clang。
压测时停止其他构建和压测；选择 affinity 允许的空闲 CPU。

执行（从已有 richyreachy/zvec checkout 根目录开始）
  git fetch origin
  git checkout fix/legacy-matrix-distance-performance
  git pull --ff-only origin fix/legacy-matrix-distance-performance
  export ZVEC_RECORD_DEPS="$PWD"
  git cat-file -e e2ac9ee02a72b2da2265003c17b27357942a2d0d^{commit}
  git submodule update --init --recursive \
    thirdparty/googletest/googletest-1.10.0 \
    thirdparty/RaBitQ-Library/RaBitQ-Library-0.7.0

交接包已随仓库提交，随后执行：
  export ZVEC_RECORD_PACK_DIR="$PWD/artifacts"
  (cd "$ZVEC_RECORD_PACK_DIR" && sha256sum -c ivf-record-alignment-handoff-20261116.tar.gz.sha256)
  export ZVEC_RECORD_WORK=$(mktemp -d "${TMPDIR:-/tmp}/zvec-record-alignment-XXXXXXXX")
  mkdir "$ZVEC_RECORD_WORK/handoff"
  tar -xzf "$ZVEC_RECORD_PACK_DIR/ivf-record-alignment-handoff-20261116.tar.gz" -C "$ZVEC_RECORD_WORK/handoff"
  (cd "$ZVEC_RECORD_WORK/handoff" && sha256sum -c SHA256SUMS)
  python3 "$ZVEC_RECORD_WORK/handoff/tools/record_alignment.py" \
    --bundle "$ZVEC_RECORD_WORK/handoff" --deps "$ZVEC_RECORD_DEPS" \
    --out "$ZVEC_RECORD_WORK/results" --jobs 4 --cpu 9 --sample-ms 50

将 --cpu 9 换为本机允许且空闲的 CPU；省略时选最小允许 CPU。
输出目录必须不存在。prepare-only / allow-non-x86 不能作为原生 x86 验收。
失败也须保留输出目录并回传，不修改阈值、不加过滤器、不关闭 sanitizer 检查。

覆盖与验收
1. 两版 53 个相关测试程序全跑；旧索引 200 份 fixture 兼容性测试全跑。
2. 新测试 turbo_record_alignment_test：
   - INT8/INT4，量化/反量化，偏移 0..7，多个维度，逐字节验证旧格式；
   - IP/L2/cosine 的 single、batch、many，32 records × 3 queries，
     多种尾部长度/偏移、batch 1/3/4/5/9/32；double 独立参考、边界哨兵、输入不变；
   - Scalar/AUTO/SSE2/AVX2/AVX512/VNNI 在普通和 sanitizer 两套构建都必须实际执行。
   - 继续要求上一轮 AVX2 joint、FP16 AVX2、record metadata fallback 测试实际通过。
3. 两版独立全插桩 ASan+UBSan 构建，检查所有 compile_commands：
   matrix、many_to_many、IVF legacy、IVF searcher、新 record alignment 共 5 个程序。
   ASan 默认 alloc_dealloc_mismatch 开启；UBSan alignment/vptr 开启。
   不过滤失败，不加 suppression，不使用 fno-sanitize。仅泄漏检测关闭。
   UBSan halt_on_error=0 用于收集全部报告，不能凭退出码 0 判定通过。
4. 基线应复现未对齐访问（加入新测试后报告数可超过上一轮 89 条）。
   候选要求所有这类报告为 0；即使与基线相同，也不能验收残留未对齐访问。
   候选出现任何其他 ASan/UBSan 报告也标 SANITIZER_FAILED，并回传位置及完整调用栈。
   不通过修改测试或阈值掩盖报告。
5. 两轮 288 项实际查询，顺序 before→after、after→before；任一轮 >5% 回退项
   再交替复测两轮。Top-K ID/顺序/扫描次数严格一致，分数继续使用既有 1e-4 界。
   输出按 Raw-FP32/FP16/INT8/INT4、Record-INT8/INT4 及 IP/L2 分组的加速比，
   列出持续回退明细。不能只报总体几何平均。
