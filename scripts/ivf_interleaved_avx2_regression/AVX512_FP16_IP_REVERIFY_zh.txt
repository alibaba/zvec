FP16 IP AUTO 回到 AVX2：Linux x86 复验说明
2026-11-17

目标与版本
本轮唯一生产修改：get_interleaved_many_to_many_distance_func 的 AUTO 模式
跳过 FP16 + IP 的 AVX512 行，继续匹配 AVX2；显式 kAVX512 不跳过。
FP32 IP/L2 和 FP16 L2 的 AUTO 优先级保持 AVX512；距离内核和 IVF 调用点未改。
旧候选 54e990b774b91d1c8e71d0ef0e66161432ea73e9 在五项 FP16 IP shared
查询出现可重复的 8.3%～16.4% 耗时增加，本次针对分派止退。

本包主对照仍为 5f489fd4debbf4efc0b32d4e0e90d0741dc65a02（原 AVX2，
已有 record 对齐修复）→当前修复候选。这能同时验证 FP16 IP 恢复到原基线，
以及 FP32 的 AVX512 收益保留；不能仅与慢版本 54e990b7 比较就宣布无回退。
包内另附 policy-fix-vs-54e990b7.patch，仅含本次生产修复，便于审查追溯。
两侧测试使用相同最新测试补丁；旧基线没有 AVX512，相关专项跳过属预期，
候选在普通与 sanitizer 两套构建中必须实际运行。

本轮代码、macOS 报告/证据、复验工具和独立包随本次分支提交归档。
文件：artifacts/ivf-avx512-fp16-ip-auto-handoff-20261117.tar.gz 及 .sha256。
包内 SHA256SUMS 覆盖每个文件，before/after-source-sha256.json 校验完整冻结源码。
不要使用旧 20261116 包：其验收条件是四组 AUTO 全选 AVX512，已不适用。

执行（从服务器已有 richyreachy/zvec checkout 根目录开始）
先按交接消息固定到本次提交；以下命令以当前分支包含该提交为前提：
  git fetch origin
  git checkout fix/legacy-matrix-distance-performance
  git pull --ff-only origin fix/legacy-matrix-distance-performance
  export ZVEC_POLICY_DEPS="$PWD"
  git submodule update --init --recursive \
    thirdparty/googletest/googletest-1.10.0 \
    thirdparty/RaBitQ-Library/RaBitQ-Library-0.7.0
  export ZVEC_POLICY_PACK="$PWD/artifacts"
  (cd "$ZVEC_POLICY_PACK" && sha256sum -c ivf-avx512-fp16-ip-auto-handoff-20261117.tar.gz.sha256)
  export ZVEC_POLICY_WORK=$(mktemp -d "${TMPDIR:-/tmp}/zvec-avx512-policy-XXXXXXXX")
  mkdir "$ZVEC_POLICY_WORK/handoff"
  tar -xzf "$ZVEC_POLICY_PACK/ivf-avx512-fp16-ip-auto-handoff-20261117.tar.gz" -C "$ZVEC_POLICY_WORK/handoff"
  (cd "$ZVEC_POLICY_WORK/handoff" && sha256sum -c SHA256SUMS)
  python3 "$ZVEC_POLICY_WORK/handoff/tools/avx512.py" \
    --bundle "$ZVEC_POLICY_WORK/handoff" --deps "$ZVEC_POLICY_DEPS" \
    --out "$ZVEC_POLICY_WORK/results" --jobs 4 --cpu 9 --sample-ms 200

原生 Linux x86_64，CPU 必须支持 AVX512F/F16C/AVX2/FMA，建议同一 Xeon 6982P-C。
CMake>=3.26、Ninja、Python>=3.9、GCC/Clang。--cpu 9 换成允许且空闲的 CPU。
避免其他构建/压测同时运行，保留 CPU affinity、lscpu、可获取的频率/负载信息。
输出目录必须不存在；prepare-only/allow-non-x86 不能当作原生验收。
工具出现 correctness/sanitizer/构建失败时保留证据，不调整阈值或配置绕过。

分派验收（候选四组均显式 AVX512=1、AVX2=1、POLICY_OK=1）
类型/度量 | AUTO_IS_AVX2 | AUTO_IS_AVX512
FP16 IP   | 1 | 0
FP16 L2   | 0 | 1
FP32 IP   | 0 | 1
FP32 L2   | 0 | 1
最终检查：interleaved_dispatch_probe --require-avx512-policy。
旧字段 joint_avx512_ready=0 是预期（四组不再全选 AVX512）；
joint_avx512_fp16_ip_policy_ready 必须为 1，不能使用旧 --require-avx512 判定。

正确性与 sanitizer
- 主工具运行两侧 53 个相关程序，外加旧索引 fixture 兼容测试。
- 候选普通及 ASan+UBSan 两套均要求：
  Avx512Fp16IpAutoUsesAvx2 实际执行，检查五种行数的 AUTO/显式选择，
  缺 AVX2/FMA 时 AUTO 不偷偷回到 AVX512；显式 AVX512 仍可获取。
  Avx512JointInterleavedQueriesAndNoAllocations 和 Avx2Joint... 均实际运行，
  包含 FP16/IP 显式 AVX512 数值测试与 AVX2 输出相等、无分配、边界检查。
  FP32/FP16 的 IP/L2 分派、FP32 累加、特性门控测试全部通过。
- 两侧 matrix/many_to_many/IVF legacy/IVF searcher/record alignment 五程序
  全插桩 ASan+UBSan；alignment/vptr/alloc_dealloc_mismatch 保持开启，仅关闭泄漏检测。
  不凭退出码0判断，无论新旧任何 sanitizer 诊断都必须回传，不自动接受。

完整性能与强制专项
主工具两轮各288项实际 IVF search_impl 查询，5个>=200ms样本取中位数，
before→after / after→before；任一轮>5%回退项自动逐项交替复测两轮。
Top-K ID/顺序/扫描次数一致，分数沿用原1e-4界。按类型、度量、batch=1/>1报告。
即使完整回归通过，也必须对原来的五项运行长采样，避免低采样掩盖回退：
  python3 "$ZVEC_POLICY_WORK/handoff/tools/focused_fp16_ip.py" \
    --results "$ZVEC_POLICY_WORK/results" --out "$ZVEC_POLICY_WORK/focused" \
    --cpu 9 --sample-ms 1000

专项仍用上述原AVX2基线A与修复候选B：5项×6 block×(4个ABBA/BAAB槽+2个AA槽)，
共180次，每槽5个>=1s样本。每block旋转案例顺序，保存原始timings/Top-K和二进制hash。
五项都是 Raw-FP16/IP/shared：
(dim,nprobe,batch)=(128,8,32),(768,1,32),(768,1,8),(768,8,32),(768,8,8)。
Top-K/分数文本及扫描量逐槽一致；输出配对 before/after 加速比及95%区间、A/A对照。
整区间>=1/1.05为PASS；整区间<1/1.05为确认回退；跨阈值为REVIEW_REQUIRED。
不得用“相比慢版本54e990b7更快”替代“恢复到5f489fd4基线”的验收。

实际叶子扫描命中（独立于计时）
- 用gdb子进程或perf证明 FP16/IP batch=32 的 IVFEntity::search_many 叶子扫描
  命中 avx2::kernel<Float16,...,IP>；不是质心普通distance/batch。
- FP32 IP/L2 及 FP16 L2 仍须有 AVX512 joint lambda 的叶子调用栈/采样证据。
- 显式 AVX512 FP16 IP 入口则由强制专项实际数值计算证明保留。
- 源码只调整getter策略，保存前后热内核反汇编可确认算法未改；不要根据频率
  字段缺失就断言降频或无降频。探针和真实查询栈两种证据都要提供。
