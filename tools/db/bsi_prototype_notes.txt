整型 BSI 实现与验证范围

2026-11-14 收敛：移除采样、BSI 命中量预估和缓存统计，简化状态与查询路径；只做相关单元测试，
不运行 benchmark。后面的性能数字是上一版本的历史记录，不代表此次精简后的结果。

已实现
- 一个字段、一个 segment 使用统一 segment docID，不划分 docID 子段。
  TERM_BSI 支持单值 INT32、INT64、UINT32、UINT64；始终保留 term posting。
- 单结果 C API 递推，按低位到高位计算 GT/GE，LT/LE 通过有界取反得到。
  跳过初始空集/全集上的恒等运算；结果直接转移所有权，无返回前深拷贝。
- writing 切片常驻可修改内存，以列内 shared_mutex 协调切片更新、BSI 查询、flush
  和 seal。NULL bitmap 使用自身的并发保护。seal 保留同一个 BsiState 和锁。
  sealed BSI 查询也持有共享锁，以保护与 seal 重叠的生命周期。
  存量 term/NULL 查询不持 BSI 锁；移除列级 dropped 状态，drop 由上层排除查询和写入。
- insert 保留原有 term Merge，入口不持 BSI 锁；update_bsi 内部持独占锁更新切片
  和 dirty_slices，返回后才由 update_doc_id_limit 推进公共 doc_id_limit_。NULL 写入先
  更新自身 bitmap，再推进相同上界。没有额外的逐行 RocksDB BSI Merge。
  insert 与 flush/seal/drop 的互斥沿用上层 collection/segment 约束。
- 删除 BSI 专用上界及持久化 key，恢复直接使用列级 doc_id_limit_。BSI 查询先读取
  一次公共上界，再读取 NULL 状态；全集构造和有界取反使用同一份局部上界。
  新切片与旧上界短暂并存只涉及尚未完成写入的 docID，filter 只测试有效候选。
  内存不再维护 max_id_；旧 max_id 元数据在 open 时局部转换，flush 时由公共上界推导。
- flush 只序列化脏切片，每个脏切片仍是完整快照 Put；与 NULL、公共 docID 上界
  在同一个 WriteBatch 写入。Write 失败不清除脏标记。
  普通 open 从 RocksDB 恢复可写状态；相同 docID/值的 WAL replay 幂等，
  即使 term 已经存在，也必须重新更新 BSI。
- seal 在准备好 frozen 数据和缓存后写 sealed 标记，再发布只读状态。
  查询结果独立拥有 bitmap，indexer 关闭后仍可使用；读取/解码错误返回失败。
  open 与 seal 共用切片/缓存加载逻辑，不再在 BsiState 中重复存储 cache_mode。
- sealed 使用 portable frozen 视图，有三种正式配置，均使用相同比较算法：
  RESIDENT：打开时加载全部切片，保持序列化 buffer 和 frozen header。
  ON_DEMAND：每次 MultiGet 实际参与计算的切片，临时视图随查询释放。
  LRU：按需加载，缓存 buffer 和 header；预算不足或切片过大时退到查询临时所有权。
  LRU 预算按字段、按 segment 生效；默认 64 MiB；writing 不受此预算限制。
  实验环境变量 ZVEC_BSI_BENCH_NONRESIDENT 已移除，改用持久化参数。
- C++、Python 和 C API 均支持 layout/cache mode/cache bytes；manifest、
  clone、pickle 和 Python 类型声明同步更新。切换配置使用已有 create_index 重建路径。
- 缓存策略和预算继续生效；移除 CollectionStats 中的 BSI 内存字段及内部统计接口。
- search 保持 term 召回；search_filter 的范围条件启用 BSI。
  BSI 允许未插入 docID 的空洞，仅用于实际候选点的 membership 判断。
- BSI 不维护在线样本，不生成或加载 CDF，也不预估命中量。向量查询中的 BSI
  evaluate_ratio 明确返回 NOT_SUPPORTED；范围条件直接构造 membership filter，
  不按 bitmap count 枚举 ID，避免空洞进入候选。
  查询执行时记录是否实际使用 BSI；仅含 term 的结果恢复原来的 count 阈值判断和 ID 枚举，
  包括 TERM/TERM_RANGE 的范围与组合条件、TERM_BSI 字段上的 EQ/IN/NULL 条件。
  原有 TERM_RANGE CDF 及正排优化保留，不再额外以 CDF 提前决定向量召回方式。
  纯标量召回、等值和 IN 继续使用 term；FTS 保留原有流程。
  空结果仍构造拒绝全部候选的 filter，避免空 term posting 与 BSI 做 AND 后失去过滤。
- 明确持久化 exclusive docID 上界，修复空 sealed 索引补集和 UINT32_MAX 溢出。
- benchmark 的 scalar_query 测量过滤 bitmap 构造，明确不是纯标量召回性能。

使用示例
Python:
  params = zvec.InvertIndexParam(
      layout=zvec.InvertIndexLayout.TERM_BSI,
      bsi_cache_mode=zvec.BsiCacheMode.LRU,
      bsi_cache_bytes=64 << 20)
  collection.create_index(field_name="dataTime", index_param=params)

C++:
  auto params = std::make_shared<InvertIndexParams>(
      InvertIndexLayout::TERM_BSI, false, BsiCacheMode::LRU, 64ULL << 20);

C:
  zvec_index_params_set_invert_layout(params, ZVEC_INVERT_LAYOUT_TERM_BSI,
                                     ZVEC_BSI_CACHE_LRU, 64ULL << 20);

历史性能记录（提交 1a4c5747，精简前）
- 复用 issue #868 场景：1000 万随机 INT32，dataTime > 536870911。
- 固定 seed=868，准确命中 7,498,740；混合检索使用同一份 62 维合成向量图。
- 191 固定 CPU 0-7，1/8 并发，各三轮 3 秒；每轮校验全部标量命中或 256 个 ANN 结果。
- TERM_RANGE 和三种 BSI 使用同一个二进制；数据已 sealed/compacted，BSI 没有待合并 operand。
- 常驻组在打开时全量加载，初始化发生在计时前；非驻留组将读取和创建视图计入查询。
  两组都经过预热，非驻留不等于每次读取物理磁盘，操作系统与 RocksDB 缓存仍有效。
- 主场景单线程 bitmap 构造中位耗时：RANGE 4.925 ms，RESIDENT 0.318 ms，
  ON_DEMAND 1.529 ms，LRU 0.318 ms；LRU 此条件只保留约 3.62 MiB，常驻约 38.59 MiB。
- 相邻阈值 536870910 需要全部切片：RANGE 4.741 ms，RESIDENT 4.278 ms，
  ON_DEMAND 20.924 ms，LRU 4.258 ms。按需读取并非对所有条件都有优势。
- 混合检索本轮只回归 RANGE/RESIDENT：单线程 6.306/2.138 ms，8 线程 544/2375 QPS。
  复用的旧数据没有新样本，混合检索规划使用 CDF；新样本的 correctness 已测试，
  此轮不代表新样本在 1000 万规模下的规划耗时基准。
- 100 万随机整数、单次构建：BSI 每 1 万条 flush 的累计快照 WriteBatch 为 204.27 MiB，
  每 10 万条为 22.37 MiB，只在 seal 写为 4.01 MiB。包含元数据，非物理磁盘写字节。
  BSI 插入阶段耗时（含 flush）分别 3.167/2.383/2.148 s；RANGE 为 2.004/1.851/1.624 s。
- 详细报告及原始结果：build.release/bsi-perf-868-results/hardening/report.html。
  查询共 60 次，构建/重开共 12 次，所有结果校验通过；生命周期数据未多轮取中位数。

已约定的边界及后续工作
1. 按方案一，不引入 segment 整行事务、回滚或 fail-stop。term/BSI 后续的 FTS/向量
   失败及 docID 复用属于共享写路径问题，另行修复。列内锁不是跨索引的事务保证。
2. float 单独实现；旧实验 BSI 格式迁移不纳入本地开发阶段的兼容承诺。
3. 布局由用户显式选择，保留已有正排优化；BSI 暂不支持命中量预估，也没有统一校准的
   BSI/term/正排自动成本模型。后续有明确需求时再单独实现统计。
4. 脏切片仍是全量 Put，随机数据会修改几乎所有位。增量持久化和更低写放大继续评估；
   不分 docID 子段。LRU 只限制保留缓存，不能限制可写状态、临时 buffer 或总 RSS。
5. 已验证上述列级故障与 WAL 恢复，不等于覆盖完整磁盘错误、segment 版本提交、
   WAL 删除和机器断电矩阵。WriteBatch 成功不等于持久化完成，继续依赖既有的
   全部 CF flush → 版本提交 → WAL 清理顺序。
6. 查询侧检查读取、解码和可检测的分配失败；CRoaring 原地操作 OOM 仍沿用库语义，
   不承诺任意内存耗尽后的整行可恢复性。共享生命周期的长时间压力验证可继续补充。

本版不引入 segment 级事务发布协议，也不要求 EQ/IN 等原有 term 查询遵守 BSI 连续前缀。
