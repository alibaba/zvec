Cohere 100K MemoryBlock migration experiment

Start with report.txt for results and limitations. results.json contains all
96 measured runs; hnsw_long_confirmation.json contains the four additional
30-second runs. Both compare main 13fd088b with migration commit ffabef5c.
The later ccef64bb commit only fixes tool headers and was not benchmarked.

The included programs are snapshots of this local macOS experiment, not a
portable benchmark entry point. They retain the original workspace, SDK,
compiler and dataset paths. Adjust these paths before using another machine.
Data, built indexes, binaries, source archives and logs are not committed.
methodology.json records the data hashes and measurement conditions.

Prerequisites for repeating the experiment:
1. Prepare the first 100,000 source vectors with their original keys, the
   1,000 queries, and exact FP32 cosine top-100 neighbors for this subset.
   The original preparation used the local index/make_10k_subset.py helper;
   that pre-existing local helper is not included in this snapshot.
2. Supply the existing CMake compilation database and built third-party,
   ailego and turbo libraries referenced by build_binaries.py. Compile both
   commit snapshots with build_binaries.py, then run compile_bench.py.
3. Create cosine_indexes and build each configs/*.yaml using main/builder.
   Both versions must read the same indexes. Build paths are in each config.
4. Validate Flat against the exact neighbors, then create the local VALIDATED
   and HARNESS_READY marker files before running run_benchmarks.py. The runner
   waits for these markers; it reuses existing runs/*.log files when present.
   Use a fresh result directory for a new experiment to avoid mixing runs.
5. Capture the matrix runner's output in runs_resumed.log. confirm_hnsw.py
   waits for ALL COMPLETE in this file before running the extra HNSW trials.
6. Run render_report.py to regenerate report.txt, summary.json and summary.csv
   from the JSON results. This step requires neither data nor built binaries.

The reported recall is the untimed validation pass, not every timed query.
The 64 MiB runs have few timed queries and show exploratory trends only.
RSS conversion in bench.cc uses macOS ru_maxrss units (bytes).
