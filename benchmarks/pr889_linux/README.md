# PR #889 Linux measurement harness

This harness implements the PR's workload shape with a new deterministic Linux
dataset. The macOS generator and collections were not available; matching the
seed does **not** make the generated rows or graph identical to the macOS run.
The generator uses explicit SplitMix64 transformations, not implementation-defined
`uniform_real_distribution`: FP32 vectors are sampled uniformly from `[-1, 1)`,
normalized with a double-precision squared norm and a FP32 scale. Queries use a
separate stream. `dataTime` is an independent uniform 31-bit integer. The build
manifest records the resulting match count.

Defaults: 10,000,000 rows, dimension 62, COSINE, INT8 HNSW M=16 and
efConstruction=200; `pid` INT64, `mail` STRING, indexed `dataTime` INT32; final
`topk=21`, ef=300; 1024-query pool, seed=868, eight engine query workers.
Collections are optimized, closed, then opened read-only with mmap. The build
checks the HNSW schema and read-only/mmap options. The current storage debug API
can reject a combined INT8 HNSW index after seeing its Flat refiner first; that
diagnostic is preserved, and DEBUG open logs supply storage/chunk evidence.

## Build

Use the root CMake hook to link internal cache counters while preserving the
production library's public symbol policy:

```sh
cmake -S . -B <build> \
  -DCMAKE_PROJECT_zvec_INCLUDE="$PWD/benchmarks/pr889_linux/project_hook.cmake" \
  <normal build flags>
cmake --build <build> --target pr889_filter_bench -j16
```

The hook creates a benchmark-only static interface from the same packed SDK
archives and dependencies as the shared library. JIT ON links the real
`ScalarDocFilter::CacheStats()` implementation. No production source changes
are needed for this target.

A public-API-only build is also possible, but its cache fields are `null` and it
cannot establish fast-path use:

```sh
cmake -S benchmarks/pr889_linux -B <harness-build> \
  -DZVEC_LIBRARY=<absolute-path-to-libzvec.so>
cmake --build <harness-build>
```

## Data and runs

```sh
<build>/bin/pr889_filter_bench --mode build --path <new-collection> \
  --rows 10000000 --build-workers 16 --output <build-manifest.json>
python3 benchmarks/pr889_linux/run_matrix.py \
  --binary <build>/bin/pr889_filter_bench --collection <collection> \
  --output <new-results-dir> --post
```

For a harness smoke check, use 20,000 rows and `--count 128 --warmup 32
--quality-count 32 --runs 1` in the matrix script. Do not call smoke numbers
10M performance measurements. Stop other builds and compute jobs before taking
performance results.

Each timed run is a new process. The script rotates variant order over three
repetitions and tests one/eight concurrent clients. A separate first query is
measured (including validation), then each client performs 1024 warmup queries.
The timed budget defaults to 4096 queries **in total**, spread evenly over
clients. Mean/p50/p95/p99 API latency brackets only `Collection::query`; wall
QPS includes validation, post-filtering, disposal, thread start synchronization,
and completion notification. Query objects are preconstructed. Every returned
row is checked against independently regenerated scalar fields and the
predicate, and every timed query must return 21 rows. Raw API latency samples
are sorted before saving; they are not a chronological trace.

`--count` can increase the matched timed-query budget for more stable short
Linux runs. Record the actual budget when comparing with the macOS PR table.

Routing uses invert-to-forward ratio 0.5 (forward) or 0.9 (inverted). Runtime
`ZVEC_SCALAR_JIT=0` selects Arrow fallback in the same JIT-capable binary.
Unfiltered and post-filter paths remove the predicate from the engine query.
The post-filter trims the returned candidates to the first 21 matching rows.

Quality checks compare complete ordered IDs, round-trippable FP32 scores and
all scalar fields over the 1024 queries, both fixed threshold and a deterministic
varying-threshold set with roughly 69%–81% matching rows. They assert actual JIT
compilation/cache hits when counters are available. All supported exact paths
must match Arrow. Post-filter quality is top-21 set overlap with filtered ANN,
**not brute-force recall**. The optional post matrix covers 64/300, 64/400,
64/600, 128/1200, 256/2048, 300/300, 400/400 and 600/600 candidate-topk/ef
configurations. topk=ef=1200/2048 receive quality tests only. Same-ef comparisons
check complete ordered results, and rankwise COSINE-distance comparisons help
interpret why agreement with one ANN reference need not increase with ef.

The runner writes command/environment records, binary hashes, quality dumps,
per-run JSON, raw samples, cache counters and median summaries. It refuses to
overwrite run files. It does not upload artifacts or modify the PR.

## Benchmark-only hardcoded comparator

`hardcode.patch` is generated by `make_hardcode_patch.py`. Apply it only in a
separate benchmark source tree, build with JIT ON and
`-DPR889_BENCH_HARDCODE=1`, and pass the resulting binary via
`run_matrix.py --hardcode-binary <binary>`. No production runtime option is
introduced. With the macro absent, the existing JIT path is unchanged.

The comparator accepts only a bound `dataTime` INT32 column greater than a
valid INT32 literal, rejects nullable data, binds immutable chunk pointers and
the threshold once, and uses the same uniform-stride/binary-search row routing.
It preserves snapshot ownership. Evaluation directly reads the INT32 value and
compares it without JIT compilation, per-row Arrow fetching, or locking. The
matrix verifies exact fixed/varying results and zero compilation count. This
comparator measures a deliberately restricted implementation; it is not a
supported backend or a substitute for the general predicate tests.

## Independent wheel oracle

```sh
ZVEC_SCALAR_JIT=1 <wheel-venv>/bin/python \
  benchmarks/pr889_linux/persisted_oracle.py \
  --path <new-or-existing-oracle-collection> --output <oracle-on.json> --debug
ZVEC_SCALAR_JIT=0 <wheel-venv>/bin/python \
  benchmarks/pr889_linux/persisted_oracle.py \
  --path <same-oracle-collection> --output <oracle-off.json>
```

This is a recreated coverage test: 19 predicates × three queries, 512 persisted
rows, unquantized FP32 squared L2, ef=1024 and topk=10. An independent Python
predicate evaluator and exhaustive distance calculation check IDs, rank,
scores and scalar fields. Cases include numeric comparisons, ranges, nullable
logic/null tests, boolean equality, string comparisons, LIKE, numeric/string
IN, NOT IN, and unsupported `array_length` fallback. It does not reproduce the
private macOS oracle's exact 57 queries and does not establish JIT routing by
itself; pair it with DEBUG logs and direct scalar tests.

An already built ON tree can generate the hardcode comparator without a full
rebuild or changes to production files:

```sh
python3 benchmarks/pr889_linux/prepare_hardcode.py \
  --build <on-build> --output <new-hardcode-dir> --ninja <path-to-ninja>
```

The script saves a source overlay, compiles the two changed objects with the
original compiler flags, replaces only those objects in a private copy of the
packed DB archive, and replays the ordinary benchmark link. A manifest records
commands and hashes. Rebuild/relink it when the harness or ON library changes.

## Historical strategy sweep protocol

The matched comparison above retains the 4096-query budget and API latency.
A separate duration-based sweep uses the unmodified upstream binary for every
strategy and records request wall latency through validation and result disposal:

```sh
python3 benchmarks/pr889_linux/run_matrix.py \
  --binary <on-build>/bin/pr889_filter_bench \
  --baseline-binary <upstream-binary> --collection <collection> \
  --output <new-sweep-results-dir> --sweep --post --seconds 20
```

This times no filter, inverted, upstream legacy forward, and eight post-filter
settings, at one/eight clients for three runs. topk=ef=1200/2048 remain quality
only. `--seconds 20` takes precedence over `--count`; JSON `count` is the actual
number of completed timed queries, and elapsed time includes the final in-flight
requests. Cache-hit checks use that actual count. `mean_request_ms` brackets the
query, post-filtering/validation and result destruction, while `mean_api_ms`
continues to bracket only the API call. QPS includes the full loop and thread
synchronization. Both raw sample arrays are saved sorted.

`--skip-quality` is available only for repeat timings after archiving successful
quality checks for the exact binaries/collection. Keep the original quality
artifact links with any such results.

The oracle explicitly enables range optimization on the indexed INT32/string
fields; Python's `InvertIndexParam` defaults differ from the C++ defaults.
Nullable Python result fields may be omitted by the API, so the oracle normalizes
missing keys to `None` and still rejects unexpected field names and values.
