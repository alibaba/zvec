# FhtKac 旋转器维度约束分析

## 1. 当前策略

`RecordRotator::init` 采用一刀切的判定逻辑：

```cpp
bool use_fht = (rotator_type == RecordRotatorType::FhtKac) && (dimension % 64 == 0);
```

- `dim % 64 == 0` → FhtKac（O(d log d)）
- 其余 → MatrixRotator（O(d²)）

**问题**：`64` 这个常量是 AVX-512 编译产物的约束，但被无条件地应用于所有平台（含 AVX2、SSE2、NEON、标量），导致大量维度（如 96, 160, 192 在 AVX2 平台上）不必要地退化为 O(d²) 的 MatrixRotator。

---

## 2. 算法组成与职责

FhtKac 旋转由三个原语组成 4 轮迭代：

| 原语 | 职责 | 数学约束 |
|------|------|---------|
| `flip_sign` | 随机符号翻转（对角 ±1 矩阵） | 无（逐元素操作） |
| `fht_inplace` | 快速 Hadamard 变换（正交混合） | 操作长度**必须是 2 的幂** |
| `kacs_walk` | Kac 随机游走（蝶形加减，用于非 2 的幂维度的归约） | 操作长度为偶数时**范数缩放均匀**；奇数时可逆但缩放不均 |

其中 `fht_inplace` 始终作用于 `trunc_dim = floor_pow2(dim)`，自然满足 2 的幂约束。
`kacs_walk` 和 `flip_sign` 作用于完整的 `dim`。

---

## 3. 数学层面的约束

### 3.1 FHT：2 的幂（已解决）

`fht_inplace` 要求输入长度为 2 的幂。代码通过 `trunc_dim = floor_pow2(dim)` 取最大 2 的幂子集，FHT 仅作用于此子集。对所有 dim ≥ 2 均有效。

### 3.2 Kac walk 的可逆性与范数缩放

`kacs_walk` 将长度为 `len` 的数组分为两半，执行蝶形运算：

```
data[i]      = x + y      (前半)
data[i+half] = x - y      (后半)
```

其中 `half = len / 2`（整数除法）。

#### 3.2.1 可逆性：偶数奇数均可逆

**偶数 len**：变换矩阵为分块对角阵，每个 2×2 块为 `[[1, 1], [1, -1]]`，行列式 = −2 ≠ 0，可逆。逆为 `inv_kacs_walk`：`(a+b)/2, (a-b)/2`。

**奇数 len**：`half = (len-1)/2`，末尾元素 `data[len-1]` 不参与蝶形运算。但正向和逆向都跳过了该元素：

```
正向: data[len-1] 保持不变
逆向: data[len-1] 保持不变
```

单步 round-trip 可完美恢复。**不可逆性并非来自 kacs_walk 本身。**

#### 3.2.2 交替 FHT 窗口的全覆盖

在非 2 的幂路径中，4 轮迭代的 FHT 窗口交替作用于两个偏移位置：

```
start = dim - trunc_dim

Round 1, 3: fht_inplace(out,       trunc_dim)  → 覆盖 [0, trunc_dim)
Round 2, 4: fht_inplace(out+start, trunc_dim)  → 覆盖 [start, dim)
```

以 dim=5（trunc_dim=4, start=1）为例：

```
Round 1 FHT: 覆盖 index [0,1,2,3]     index 4 未参与
Round 2 FHT: 覆盖 index [1,2,3,4]     index 4 参与了!
Round 3 FHT: 覆盖 index [0,1,2,3]     index 4 未参与
Round 4 FHT: 覆盖 index [1,2,3,4]     index 4 参与了!
```

**每个元素至少被 FHT 覆盖 2 轮**。信息传播路径：

```
Round 1 kacs_walk: data[2] = data[0]+data[2]（index 0 的信息混入 index 2）
Round 2 FHT:       data[4] 与 data[1..3] 混合（index 2 已携带 round 1 的信息）
Round 2 kacs_walk: data[2] = data[2]+data[4]（index 4 的信息反向混入 index 2）
```

所有元素的信息通过 **FHT 混合 + kacs_walk 扩散** 的交替传播到全维度。变换整体可逆。

#### 3.2.3 真正的约束：范数缩放均匀性

`kacs_walk` 对 len 的范数影响取决于长度奇偶性：

**偶数 len（所有元素配对）**：每对 `(x,y) → (x+y, x-y)`，范数变化：

\[
(x+y)^2 + (x-y)^2 = 2(x^2+y^2)
\]

所有元素的范数统一乘以 √2。4 轮 kacs_walk 后总缩放为 (√2)⁴ = **4**，`vec_rescale(out, dim, 0.25f)` 完美校正。

**奇数 len（末尾元素孤立）**：

- 配对元素（index 0..2h-1）：范数 × √2，4 轮后 × 4 → `0.25` 校正正确
- 末尾元素（index 2h）：值不变，范数 × 1，4 轮后 × 1 → `0.25` 错误缩小到 1/4

变换仍可逆，但**不再等距**——向量间的相对距离关系被扭曲。

> **结论：奇数维度在数学上可逆，但范数缩放不均匀导致变换不等距。** 对于后续需要归一化的场景（如量化前旋转），范数偏差会被吸收，影响有限；对于依赖精确距离的场景，可能引入误差。偶数维度是保证等距性的实用约束。

### 3.3 旋转质量考量

虽然数学上偶数即可，但旋转质量（随机化程度）与 `trunc_dim / dim` 比值有关：

| dim | trunc_dim | 比值 | 备注 |
|-----|-----------|------|------|
| 128 | 128 | 1.00 | 精确 2 的幂，最优 |
| 192 | 128 | 0.67 | 良好 |
| 384 | 256 | 0.67 | 良好 |
| 96 | 64 | 0.67 | 良好 |
| 100 | 64 | 0.64 | 可接受 |
| 130 | 128 | 0.98 | 极好 |
| 258 | 256 | 0.99 | 极好 |

当 `trunc_dim / dim` 较低时（如 dim=129, trunc=128, ratio=0.99 但只有 1 个剩余元素），4 轮交替的 kacs_walk 足以将信息扩散到全部维度。实际上，只要 dim 不太小，旋转质量都可接受（偶数维度范数均匀，奇数维度有轻微缩放不均）。

## 4. 实现层面的 SIMD 对齐约束

### 4.1 `flip_sign` 各路径约束

**AVX-512**（`__AVX512F__ + __AVX512DQ__`）:
```
kChunk = 64，每次处理 64 个 float
memcpy(&mask_bits, &flip[i/8], sizeof(uint64_t))  → 读取 8 字节
→ 要求: dim % 64 == 0
```

**AVX2**:
```
kChunk = 32，每次处理 32 个 float
memcpy(&mask_bits, &flip[i/8], sizeof(uint32_t))  → 读取 4 字节
→ 要求: dim % 32 == 0
```

**SSE2**:
```
每次处理 4 个 float
memcpy(&bits16, &flip[i/8], sizeof(uint16_t))  → 读取 2 字节
→ 要求: dim % 4 == 0
```

**ARM NEON**（AArch64）:
```
每次处理 4 个 float（float32x4_t）
memcpy(&bits16, &flip[i/8], sizeof(uint16_t))  → 读取 2 字节
→ 要求: dim % 4 == 0
```

**标量 fallback**:
```
逐元素处理，flip[i/8] 按位访问
→ 要求: dim % 8 == 0（确保 i/8 始终为整字节访问）
```

### 4.2 `kacs_walk` 各路径约束

| SIMD 路径 | 步长 | half 约束 | dim 约束 |
|-----------|------|-----------|---------|
| AVX-512 | 16 | half % 16 == 0 | dim % 32 == 0 |
| AVX2 | 8 | half % 8 == 0 | dim % 16 == 0 |
| SSE2 | 4 | half % 4 == 0 | dim % 8 == 0 |
| NEON | 4 | half % 4 == 0 | dim % 8 == 0 |
| 标量 | 1 | 无（偶数即可） | dim % 2 == 0 |

### 4.3 `fht_inplace` 约束

FHT 仅作用于 `trunc_dim`（已是 2 的幂），始终满足约束，**不引入额外限制**。

### 4.4 综合：各路径的最低 dim 对齐要求

由于 `flip_sign` 的约束始终 ≥ `kacs_walk` 的约束，`flip_sign` 是瓶颈：

| 编译目标 | flip_sign 约束 | kacs_walk 约束 | **当前代码** | 瓶颈 |
|----------|---------------|---------------|-------------|------|
| AVX-512 | dim % 64 == 0 | dim % 32 == 0 | dim % 64 == 0 | flip_sign (memcpy 8B) |
| AVX2 | dim % 32 == 0 | dim % 16 == 0 | dim % 64 == 0 ❌ | 过度约束 2× |
| SSE2 | dim % 4 == 0 | dim % 8 == 0 | dim % 64 == 0 ❌ | 过度约束 16× |
| NEON | dim % 4 == 0 | dim % 8 == 0 | dim % 64 == 0 ❌ | 过度约束 16× |
| 标量 | dim % 8 == 0 | dim % 2 == 0 | dim % 64 == 0 ❌ | 过度约束 8× |

## 5. 过度约束的实际影响

以下常见向量维度在当前策略下被**不必要地**退化为 MatrixRotator（O(d²)）：

| 维度 | % 64 | AVX2 可用? | SSE2 可用? | 典型场景 |
|------|------|-----------|-----------|---------|
| 96 | 32 ≠ 0 | ✅ dim%32=0 | ✅ dim%4=0 | 部分 embedding |
| 160 | 32 ≠ 0 | ✅ dim%32=0 | ✅ dim%4=0 | 部分 embedding |
| 192 | 0 | ✅ | ✅ | Cohere 等 |
| 224 | 32 ≠ 0 | ✅ dim%32=0 | ✅ dim%4=0 | — |
| 320 | 0 | ✅ | ✅ | — |
| 100 | 36 ≠ 0 | ❌ dim%32=4 | ✅ dim%4=0 | 自定义 |
| 1536 | 0 | ✅ | ✅ | OpenAI |
| 384 | 0 | ✅ | ✅ | Cohere |

96, 160, 224 维在 AVX2 平台上完全可以走 FhtKac 路径，但被当前 dim%64 判定误杀。

## 6. 奇数维度的可行性

**结论：可逆，但不等距。**

| 方面 | 分析 |
|------|------|
| `kacs_walk` 可逆性 | 末尾元素正向/逆向均跳过，单步 round-trip 可恢复 |
| 交替 FHT 覆盖 | Round 2/4 的 FHT 窗口覆盖末尾元素，信息通过 4 轮迭代扩散到全维度 |
| 整体可逆性 | 每个原语各自可逆，组合也可逆 |
| 范数缩放 | 配对元素 ×4（被 0.25 校正），末尾元素 ×1（被 0.25 错误缩小）→ **不等距** |

奇数维度的实际影响：
- **量化前旋转**（后续有归一化）：范数偏差被归一化吸收，影响有限
- **精确距离计算**（如 refiner 重排序）：不等距会引入距离误差
- **cosine 相似度**：仅依赖方向，范数缩放不影响结果

实践中，奇数维度的向量极少见。若需支持，可在 `vec_rescale(0.25f)` 前对末尾元素做单独校正，或直接 fallback 到 MatrixRotator。

---

## 7. 总结

| 约束来源 | 约束条件 | 性质 |
|----------|---------|------|
| FHT（数学） | trunc_dim 为 2 的幂 | 已由 `floor_pow2` 解决 |
| Kac walk 可逆性（数学） | 偶数奇数均可逆 | **不构成约束** |
| Kac walk 等距性（数学） | dim 为偶数时范数缩放均匀 | 实用约束（奇数可逆但不等距） |
| flip_sign（SIMD 实现） | 取决于编译目标：64/32/4/8 | 实现层面的约束 |
| kacs_walk（SIMD 实现） | 取决于编译目标：32/16/8/2 | 弱于 flip_sign |

**当前 dim%64==0 的判定过于保守**，它将 AVX-512 的约束泛化到了所有平台。合理的策略是按编译目标分别判定：

```
编译目标     最低对齐要求    覆盖维度示例
─────────   ────────────   ───────────────────
AVX-512     dim % 64 == 0  64, 128, 192, 256, ...
AVX2        dim % 32 == 0  32, 64, 96, 128, 160, 192, ...
SSE2/NEON   dim % 4 == 0   4, 8, 12, ..., 96, 100, ...
标量        dim % 8 == 0   8, 16, 24, ..., 96, 104, ...
```

进一步放宽（添加标量尾部循环处理剩余元素）可将要求降至 **dim 为偶数**（保证等距性），但收益递减，实现复杂度增加。

---

## 8. 三种放宽方案的开销分析

### 8.0 设计原则

所有方案遵循同一原则：**dim%64==0 的热路径完全不变**。

改动方式：将当前 SIMD 循环的 `i < dim` 改为 `i < dim_aligned`（对齐部分），再追加标量尾部循环处理剩余元素。当 `dim % 64 == 0` 时，`dim_aligned == dim`，尾部循环体为空，编译器可优化掉分支判断。

每轮 rotate 调用 4 次 `flip_sign` + 4 次 `kacs_walk`；unrotate 额外调用 4 次 `inv_kacs_walk`。以下分析以 **单次 rotate** 为基准。

### 8.1 方案一：对齐到 16（dim % 16 == 0）

**init 改动**：`dimension % 64 == 0` → `dimension % 16 == 0`

**新覆盖维度**：96, 160, 224, 288, 352, 416, ...（dim%16==0 但 dim%64≠0）

**需要标量尾部的函数**（仅 AVX2 编译目标，因为 SSE2/NEON 的原生 chunk=4 已整除 16）：

| 函数 | SIMD 处理 | 标量尾部 | 尾部最大元素数 |
|------|----------|---------|-------------|
| `flip_sign` | 32 元素/次（AVX2） | 逐位标量循环 | **32**（当 dim%32==16） |
| `kacs_walk` | 8 对/次（AVX2） | 标量蝶形 | **16**（half 中未对齐部分） |
| `inv_kacs_walk` | 8 对/次（AVX2） | 标量蝶形 | **16** |

**代码改动示例**（以 flip_sign AVX2 为例）：

```cpp
#elif defined(__AVX2__)
  constexpr size_t kChunk = 32;
  // ... 常量初始化不变 ...
  size_t dim_aligned = dim & ~(kChunk - 1);  // 对齐到 32 的倍数
  for (size_t i = 0; i < dim_aligned; i += kChunk) {
    // 原有 AVX2 SIMD 代码完全不变
  }
  // 标量尾部：处理 dim_aligned 到 dim 的剩余元素
  for (size_t i = dim_aligned; i < dim; ++i) {
    if (flip[i / 8] & (1u << (i % 8))) {
      data[i] = -data[i];
    }
  }
```

**单次 rotate 额外开销**（dim=96，AVX2 编译，每轮 dim%32=0 无尾部）：

| | dim=96 | dim=160 | dim=224 |
|--|--------|---------|---------|
| dim % 32 | 0 | 0 | 0 |
| flip_sign 尾部 | 0 元素 | 0 元素 | 0 元素 |
| kacs_walk 尾部 | 0 元素 | 0 元素 | 0 元素 |
| **总额外开销** | **0** | **0** | **0** |

> 96, 160, 224 在 AVX2 上恰好满足 dim%32==0，**零标量尾部**。这是此方案的最佳收益点。

**有尾部的维度**（dim%16==0 但 dim%32==16，如 48, 80, 112, 176）：

| | dim=48 | dim=80 | dim=112 |
|--|--------|--------|---------|
| dim % 32 | 16 | 16 | 16 |
| flip_sign 尾部/次 | 16 次标量迭代 | 16 | 16 |
| kacs_walk 尾部/次 | 8 次标量蝶形 | 8 | 8 |
| 4 轮 flip_sign 尾部 | 64 次迭代 | 64 | 64 |
| 4 轮 kacs_walk 尾部 | 32 次迭代 | 32 | 32 |
| **总额外标量迭代** | **~96** | **~96** | **~96** |

约 96 次标量迭代 vs 原有 SIMD 路径约 20-30 条指令，额外开销约 **3-4× 单轮 SIMD 时间**。但对比 MatrixRotator（dim=48 需 48²=2304 次乘加），仍然快 **20×+**。

**实现复杂度**：低。每个 SIMD 函数增加 2-4 行（`dim_aligned` 计算 + 标量尾部循环）。

---

### 8.2 方案二：对齐到 4（dim % 4 == 0）

**init 改动**：`dimension % 64 == 0` → `dimension % 4 == 0`

**新覆盖维度**：100, 104, 108, 132, 156, 164, 172, 228, ...（dim%4==0 但 dim%16≠0）

**需要标量尾部的函数**：

| 编译目标 | flip_sign 尾部 | kacs_walk 尾部 | 最大尾部元素 |
|---------|---------------|---------------|------------|
| AVX-512 | dim%64≠0 时 | dim%32≠0 时 | 60（flip_sign）/ 30（kacs） |
| AVX2 | dim%32≠0 时 | dim%16≠0 时 | 28 / 14 |
| SSE2/NEON | **无**（chunk=4 整除） | dim%8≠0 时 | 0 / 6 |

**代码改动**（SSE2/NEON 只需改 kacs_walk，flip_sign 无需改动）：

```cpp
// kacs_walk SSE2 改动：
#elif defined(__SSE2__)
  size_t half_aligned = half & ~3u;  // 对齐到 4
  for (size_t i = 0; i < half_aligned; i += 4) {
    // 原有 SSE2 SIMD 代码完全不变
  }
  for (size_t i = half_aligned; i < half; ++i) {
    float x = data[i];
    float y = data[i + half];
    data[i] = x + y;
    data[i + half] = x - y;
  }
```

**单次 rotate 额外开销**（典型维度）：

| | dim=100 (SSE2) | dim=100 (AVX2) | dim=132 (AVX2) |
|--|----------------|----------------|----------------|
| flip_sign 尾部 | 0 | 4 次迭代 | 4 次迭代 |
| kacs_walk 尾部 | 2 次蝶形 | 2 次蝶形 | 2 次蝶形 |
| 4 轮 flip_sign | 0 | 16 次迭代 | 16 次迭代 |
| 4 轮 kacs_walk | 8 次蝶形 | 8 次蝶形 | 8 次蝶形 |
| **总额外** | **~8** | **~24** | **~24** |

额外开销极低。但 AVX-512 平台上 dim%4==0 但 dim%64≠0 的维度会有较大尾部（最多 60 元素），需要考虑是否对 AVX-512 平台单独保留 dim%64 约束，或者使用 **级联降级尾部**：

```cpp
// AVX-512 平台的级联尾部策略：
// 先处理 64 对齐部分（AVX-512）
// 再处理 32 对齐剩余（降级到 AVX2 intrinsics）
// 再处理 4 对齐剩余（降级到 SSE2 intrinsics）
// 最后处理 <4 的尾部（标量）
```

级联策略可将 AVX-512 上 dim=100 的尾部从 60 次标量降到 ~4 次 SIMD + ~2 次标量，但实现复杂度显著增加。

**实用建议**：对 AVX-512 和 AVX2 保留各自原生对齐（64/32），仅对 SSE2/NEON 放宽到 dim%4。这样改动最小，且 SSE2/NEON 平台的 flip_sign 天然不需要尾部。

**实现复杂度**：中等。SSE2/NEON 仅改 kacs_walk/inv_kacs_walk（各加 ~4 行）。若要全平台统一放宽到 4，需要级联尾部逻辑。

---

### 8.3 方案三：对齐到 2（dim % 2 == 0）

**init 改动**：`dimension % 64 == 0` → `dimension % 2 == 0`

**新覆盖维度**：所有偶数维度（6, 10, 14, 18, 22, 26, 30, ...）

**需要标量尾部的函数**（几乎所有维度都有尾部）：

| 编译目标 | flip_sign 尾部 | kacs_walk 尾部 | 最大尾部元素 |
|---------|---------------|---------------|------------|
| AVX-512 | dim%64≠0 | dim%32≠0 | 62 / 31 |
| AVX2 | dim%32≠0 | dim%16≠0 | 30 / 15 |
| SSE2/NEON | **dim%4≠0 时** | dim%8≠0 | **2 / 7** |
| 标量 | 无 | 无 | 0 |

**关键差异**：SSE2/NEON 的 flip_sign 原本要求 dim%4==0（`memcpy` 读 2 字节、处理 4 元素/次）。放宽到 dim%2 后：

```cpp
// SSE2 flip_sign 需要额外处理 dim%4==2 的情况：
  size_t dim_aligned = dim & ~3u;  // 对齐到 4
  for (size_t i = 0; i < dim_aligned; i += 4) {
    // 原有 SSE2 SIMD 代码不变
  }
  // 尾部：最多 2 个元素
  for (size_t i = dim_aligned; i < dim; ++i) {
    if (flip[i / 8] & (1u << (i % 8))) {
      data[i] = -data[i];
    }
  }
```

kacs_walk/inv_kacs_walk 的尾部更大：

| | dim=98 (SSE2) | dim=98 (AVX2) |
|--|---------------|---------------|
| half = 49 | | |
| kacs_walk 尾部/次 | 1 次蝶形 | 1 次蝶形 |
| flip_sign 尾部/次 | 2 次标量 | 2 次标量 |

对于小偶数维度（如 dim=6, 10），SIMD 循环几乎不执行，绝大多数工作在标量尾部中。但即便如此，FhtKac 的 O(d log d) 复杂度仍远优于 MatrixRotator 的 O(d²)。

**单次 rotate 额外开销**（典型维度）：

| | dim=98 (SSE2) | dim=100 (SSE2) | dim=130 (AVX2) |
|--|---------------|----------------|----------------|
| flip_sign 尾部/次 | 2 | 0 | 2 |
| kacs_walk 尾部/次 | 1 蝶形 | 2 蝶形 | 1 蝶形 |
| 4 轮总额外 | ~12 次迭代 | ~8 次迭代 | ~12 次迭代 |

开销极低。但注意 dim=130 在 AVX2 上：flip_sign 需处理 130%32=2 个标量尾部 + kacs_walk 需处理 65%8=1 个蝶形尾部。

**实现复杂度**：中等偏高。每个 SIMD 函数都需加尾部处理，且需要验证小维度（如 dim=6）的正确性。

### 8.4 三方案对比

| 维度 | 方案一（%16） | 方案二（%4） | 方案三（%2） |
|------|-------------|------------|------------|
| **init 阈值** | dim % 16 == 0 | dim % 4 == 0 | dim % 2 == 0 |
| **新覆盖维度** | 96,160,224,... | +100,104,108,... | +6,10,14,18,... |
| **dim%64==0 开销** | **0** | **0** | **0** |
| **典型新维度开销** | 0~96 次标量 | 8~24 次标量 | 8~12 次标量 |
| **改动函数数** | 3（AVX2） | 2（SSE2/NEON kacs 系） | 5（全部函数全部路径） |
| **实现复杂度** | 低 | 中 | 中高 |
| **测试矩阵** | 小 | 中 | 大（含小维度） |
| **对比 Matrix 收益** | 极大（96 维: 20×+） | 大（100 维: 15×+） | 大但边际递减 |

### 8.5 建议

**方案一（dim%16）是性价比最优选择**：

1. 96, 160, 224 维在 AVX2 上恰好 dim%32==0 → **零额外开销**，直接从 O(d²) 跳到 O(d log d)
2. 代码改动量最小（每个函数加 2-4 行）
3. 测试覆盖明确（只需验证 16 对齐的新维度）
4. 实践中常见的非 64 对齐维度（96, 160）全部覆盖

方案二和方案三的额外收益有限——现实中的 embedding 维度几乎总是 4 的倍数（实际上更是 8 或 16 的倍数），方案一已经覆盖了绝大部分场景。
