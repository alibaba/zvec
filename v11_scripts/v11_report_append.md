## 1. 查询映射核实与回放工具修复【实测】

### 1.1 映射语义核实

- 导出工具（ivf_rabitq_scan_diagnostic.cc）：查询循环
  `for (size_t q = 0; q < vectors.size(); ++q)`，CSV 的 query 列写入该
  下标——即【加载序行号】，非文件 qid。v10 §5.5 称其为"文件 qid"，
  与代码不符（本节修正）。
- 查询加载保持文件行序（TxtInputReader），故加载序行号 = 文件行号。
  本数据集文件 qid 恰为 0..999 且与行号一致（恒等），因此 v10 P4/P5
  【数值结论未受影响】；映射错误是潜在的，仅在乱序/非连续 qid 文件
  下会错位。
- v10 回放工具曾把 query 列当作文件 qid 并构造 qid→行号映射——语义
  错误（对本文件恰好恒等）。v11 修复：query 列一律按加载序行号消费，
  行号越界/为负/同查询重复列表均硬报错。

### 1.2 回归用例（新增，全部符合预期）

|---|---|---|---|
| (a) qid 乱序 | 行序不变、qid 置换（Random(1234)） | 诊断 CSV 与原始逐字节一致（qid 不参与计算）；回放按行号对齐 | lists/samples/results 三个 CSV cmp 全部 IDENTICAL；R3 回放 PASSED（307,273/14,828 行，max_err=0） |
| (b) 行乱序 | 行置换（Random(4321)），qid 随行移动、非连续乱序 | 采样行随行变化，回放按行号对齐 | 采样行数变为 300,636/14,833（选择到不同查询）；R4 回放 PASSED，max_err=0 |

## 2. 回放等价性验证【实测】

### 2.1 方法：生产侧采样导出 + 回放逐值比对

- 生产侧新增 `--export-scan-samples [--sample-query-stride=N]`：
  集成侧对每个 keeps≠0 块记录行 {0, 行数/2, 末行}（key、distance、
  lower_bound、coarse_dot）；专用侧对每列表记录批次 {0, 中间, 末}、
  车道 {0, 末}。stride=100 → 每侧 10 个查询。
- 回放侧新增 `--samples-int/--samples-ded --tolerance`：按 lists.csv
  记录顺序逐查询、逐列表、逐块走查（集成含 key-keep 位图），按相同
  规则消费采样行并比对 key 与三个浮点值；块数/尾块行数不匹配、末尾
  残留未消费行均硬报错。回放直接调用生产 Quantizer
  （quantize/distance/block_scanner/estimate）与生产字节，因此逐位
  一致是可能的也是达成的。PASS 要求 checked>0 且零失配。

### 2.2 发现并修复：专用侧查询准备不等价（v10 遗留缺陷）

- v10 回放以原始查询向量 + 旋转空间残差/IP 构造 g_add/g_error；
  生产路径实际为：CosineNormalizeReformer 归一化（ailego L2）→
  IvfRabitqReformer 旋转 + SplitBatchQuery → 每簇以 zvec 度量函数在
  【未旋转】质心上计算距离 → 残差范数（IP：sqrt(q²+c²−2·ip)）→
  set_g_add。
- 修复后逐位一致（修复前 smoke：17,792/17,792 行全部值失配，key 与
  结构完全正确）；v11 专用侧回放 checksum 因此与 v10 P4 不同（预期
  内）。计时代表性维持（同核同数据量），但 v10 P4 专用侧数值校验
  结论标记失效，由本节取代。

### 2.4 回放范围声明

回放执行且仅执行【粗扫估计核】：集成 = turbo 块扫描 estimate +
key-keep 位图；专用 = rabitqlib 批量估计 + 逐簇准备。不含堆维护、
精排升级（refine）、结果收集/排序/finalize。prod/unpruned 标签指
列表选择与粗扫剪枝序列（prod = 生产剪枝路径），不代表完整搜索计时。
